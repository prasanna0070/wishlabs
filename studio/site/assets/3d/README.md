# 3D assets

Everything here was made on the dev VM from real engine outputs. Nothing was modelled by hand and nothing was
generated by an image model. Build scripts, the check renders and the English-name re-preview are kept in
`studio/_out/site-3d-build/` (not deployed).

## Conventions (every GLB)

- 1 unit = 1 mm, Y up, the front of the gadget faces +Z.
- Shells and the assembly are centred on their bounding box in X and Z, with the base at y = 0.
  `board.glb` is centred on the board outline, with the board underside at y = 0 (through-hole pins reach y = -1.8).
- Compressed with `EXT_meshopt_compression` and `KHR_mesh_quantization` (glTF-Transform 4.5.1, level high,
  14-bit positions, 10-bit normals). In three.js: `new GLTFLoader().setMeshoptDecoder(MeshoptDecoder)` with
  `MeshoptDecoder` from `three/addons/libs/meshopt_decoder.module.js`. Quantization puts a scale and offset on
  each mesh node, so never zero a mesh node's transform. Move the parent group nodes instead (see the assembly).
- Plain PBR materials, no textures. Each material's `extras.hex` holds its sRGB colour.

## Shell models (`<slug>.glb`)

Node names are the engine's part names (`PRINT_Shell`, `PURCHASE_Display`, `PRINT_LedDiffuser`,
`PURCHASE_Button`, `PRINT_ButtonCap`). Every shell material was checked against `spec.json` `colors`. All of
them already carried the spec colours exactly, so none was changed. `extras.role` on each material says which:
`body`, `accent`, `detail`, `screen` (glass, roughness 0.2), `light-window` (the diffuser, alpha 0.82, blended) or
`part` (a shade the engine derived, such as a button plunger). All other materials: roughness 0.55, metalness 0.
The scene `extras` repeat the spec colours.

## Assembly (`assembly.glb` + `assembly.json`)

The full CAD assembly of the e2e v3 benchmark build: a children's bedtime story bear ("Sleepy Bear"), with every
internal part in its assembled position. No desk-bot full build existed when this was made.

- Each part is a top-level group node named as in the table below, with an identity rest transform and one
  child mesh node `<name>_mesh`. Exploded pose: `group.position.set(...explode.map(v => v * t))` for t in 0..1.
  Scene child order is the build order.
- `assembly.json`: `parts[]` with `node`, `kind` (print, purchase, pcb, cable, fastener), `label` (plain words),
  `explode` (mm), `order` (follows the build guide's step order), plus `detail` (the engineering name),
  `color`, `center`, `bbox` and `tris`. Top level: `bbox` (assembled), `explodedBbox` (at t = 1, for framing the
  camera: -70.9, -79.6, -220.2 to 70.9, 265.5, 275.3), `center`.
- How the explode vectors are made: a per-kind offset plus 15 to 20 mm along the line from the assembly centre
  (0, 94, 0) to the part centre. The shell halves part along Z (front +220, back -115). The front parts are layered
  between them: seals and light cover +95, speaker, screen, light and microphone +68, their printed holders +40,
  holder screws +14 (backed out of the holders). The circuit board drops 75 mm with its three plug-in boards lifted
  37 mm above it and the board screws between. The big button rises 95 mm above its hole in the moved front shell.
  The back screws sit 50 mm behind the back shell. Brass inserts and rubber feet stay with the front shell.
- `boardGlb`: dropping `board.glb` into the assembly frame at `translate [0, 10.4, -7.05]` puts it exactly on
  `PURCHASE_Backplane` (connector centres agree within 0.05 mm). Hide `PURCHASE_Backplane` when you swap it in.

## Circuit board (`board.glb`)

The routed backplane, re-exported on the VM with `kicad-cli pcb export glb` and the engine's flags (subst-models,
tracks, pads, silkscreen, soldermask) from a copy of `backplane.kicad_pcb`, then:

- KiCad's GLB and STEP exports carry no colours for the component models, so every component's faces were taken
  from KiCad's own VRML export of the same board, with KiCad's model colours (black plastic sockets, cream JST
  connectors, tin terminals, brown capacitors, gold contacts). All 26 components matched; 3,485 coloured faces.
- Node names: the reference designators (`J_U1A`, `J_SPK`, `R1`...) plus `board-body`, `copper-tracks-top/-bottom`,
  `pads-*`, `vias-*`, `silkscreen-*`, `soldermask-*`. Solder mask is blue (alpha 0.83), as the board's stackup says.

## Changes made on the way (all in the copies, never in the sources)

1. **shop-greeter**: the engraved shop name was a personal name. It now reads **CORNER STORE** (the "WELCOME"
   strip is unchanged). The model and its fallback still are true engine output: the same spec, with only that text
   changed, the product name set to "Welcome Chime" and one light-scene name made English, re-previewed with the
   frozen engine copy (`consumer-hardware-platform-stable`, `gstudio preview`). The same command on the unchanged
   spec reproduced the original `preview.glb` byte for byte. Spec and outputs: `_out/site-3d-build/shop-greeter-english/`.
   The lineup photo, the shop-greeter studio and life photos, and the landing copy still show or quote the old
   name, so they need the same change.
2. **board.glb**: the two silkscreen texts with the internal project codename (front and back) were removed
   before export. Everything else on the silkscreen is unchanged.
3. **assembly.glb**: the microphone cable was a 190,286-triangle sweep and is simplified to 5,999 triangles (the
   other cables are untouched). The backplane block was generic green in the CAD and is now blue (#1277BD), to
   match the board's stackup and `board.glb`. Printed parts use roughness 0.55. All positions are unchanged.

## Verification

`verify.mjs` parses every GLB with glTF-Transform (meshopt decoder) and prints the sizes, node counts, triangle
counts and bounding boxes in the table above. three.js r170 (headless Chrome, SwiftShader) loaded every file;
renders of the six shells, the assembled bear, the exploded bear (three angles, plus t = 0.5) and the board are in
`_out/site-3d-build/checks/`.
